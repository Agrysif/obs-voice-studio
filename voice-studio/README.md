# 🎙 Голосовая студия — для разработчика

Описание плагина для пользователей: [README.ru.md](../README.ru.md) · [README.md (English)](../README.md).
Здесь — как всё устроено, как собирать, проверять и выпускать новые версии.

## Сборка

Нужно: Visual Studio 2022 с C++ (CMake входит в неё), Git, установленный OBS Studio.

```powershell
.\build.ps1            # собрать
.\build.ps1 -Test      # собрать и прогнать проверки
.\build.ps1 -Install   # собрать и установить в OBS
.\build.ps1 -Package   # собрать zip в dist\ для переноса на другой компьютер
```

Или дважды щёлкнуть `Собрать и установить.cmd`.

При первом запуске скрипт `..\_shared\scripts\setup-obs-sdk.ps1 -WithQt` подготовит SDK. Он скачает заголовки
libobs той же версии, что установлена у вас, и создаст `obs.lib` и `obs-frontend-api.lib` из DLL OBS. Ещё он
скачает официальный пакет Qt от разработчиков OBS (около 250 МБ, сверяется по SHA-256) — тот же Qt 6, на котором
работает OBS. Собирать сам OBS не нужно.
**После обновления OBS** запустите `setup-obs-sdk.ps1 -Force -WithQt` и пересоберите плагин.

Если OBS открыт во время установки, `install.ps1` переименует занятую старую DLL и положит новую рядом.
Новая версия включится после перезапуска OBS.

## Проверки

- `voice-studio-test selftest` — точность смены высоты, лимитер, эквалайзер, тишина без NaN.
- `voice-studio-test latency|bench|calibrate|process <файл.wav>` — задержки, нагрузка, «Умная настройка»
  и обработка WAV-файла (можно подмешать шум: `process in.wav out.wav -40`).
- `voice-studio-obs-test` — запускает настоящий libobs без окна OBS и без вывода звука. Загружает плагин,
  подаёт речь через тестовый микрофон и нажимает элементы интерфейса: стили, режимы, «Умную настройку»,
  прослушивание, смену голоса, сравнение с оригиналом. Ещё он проверяет живой блок на настоящем фильтре
  (встраивание на место метки, уровни, спектр, запись точек эквалайзера) и сохраняет его скриншот.
- `voice-studio-update-tool selftest` — автообновление: SHA-256, проверка подписи (верная / подменённый текст /
  чужой ключ), разбор описания версии, пакет (запись, чтение, опасные пути, обрезанный файл) и установка в папку,
  где старая библиотека занята, как у работающего OBS.
- `voice-studio-ui-preview <data> show [язык]` — макет окна фильтра OBS с живым блоком и «игрушечными» данными.
  `… shot out.png [normal|hover|drag|eqoff|nosignal|update|bench] [язык]` — скриншот или замер скорости отрисовки.
- `voice-studio-demo-video <data> <ffmpeg.exe> <музыка> <out.mp4> ru|en` — демо-ролик 1920×1080 под трек
  (123 уд/мин, 35,5 с): окно фильтра в 3D, сцена трансляции, карточки функций, карусель языков. Стиль —
  киберспортивный плакат в одном синем цвете плагина: спокойная клетка, Bahnschrift Condensed и Cascadia Mono,
  векторные иконки (Qt SVG), без свечений; трансляция — в духе Twitch, но без чужих логотипов.
  Кадры считаются по виртуальному времени (живой блок шагает через `LiveBlock::step`), так что эффекты не дают
  рывков. `… stills <папка> ru|en 1.0,15.6,…` — отдельные кадры для проверки. Из него сделаны ролики и GIF в `docs/`.

## Выпуск новой версии

1. Поднимите версию в `CMakeLists.txt` (`project(voice-studio VERSION …)`).
2. Опишите изменения в `releases/<версия>/`:
   `notes.ru.txt` и `notes.en.txt` — коротко, для окна «Доступна новая версия»;
   `github.md` — описание выпуска на GitHub (RU + EN).
3. `pwsh .\release.ps1 -DryRun` — сборка, все проверки, пакет обновления, подпись, проверка подписи.
4. Закоммитьте и отправьте изменения, затем `pwsh .\release.ps1` — выпуск `v<версия>` на GitHub и проверка
   выпуска «глазами» плагина (`voice-studio-update-tool online`).

### Как устроено автообновление

```
github.com/<репозиторий>/releases/latest/download/update.txt      версия, имя и SHA-256 пакета, что нового
github.com/<репозиторий>/releases/latest/download/update.txt.sig  подпись ECDSA P-256 (SHA-256), base64 r||s
github.com/<репозиторий>/releases/download/v<версия>/voice-studio-<версия>-update.bin   DLL + переводы
```

- Плагин скачивает `update.txt` и подпись (WinHTTP, только HTTPS), проверяет подпись открытым ключом из
  `src/update/public-key.hpp` (BCrypt), затем пакет: размер и SHA-256 должны совпасть с подписанным описанием.
- Пакет `VSUPDT01` хранит только пути `bin/64bit/…` и `data/…` внутри папки плагина, без `..` и абсолютных путей.
- Установка: все файлы сначала пишутся рядом как `*.new`, затем старые переименовываются в `*.old-<время>`
  (Windows разрешает переименовать даже загруженную DLL), новые встают на их место. При любой ошибке всё
  возвращается как было. Остатки `*.old-*` удаляются при следующем запуске OBS.
- Проверка — не чаще раза в 20 часов, через 8 секунд после загрузки OBS, в фоновом потоке. Настройки —
  `%APPDATA%\obs-studio\plugin_config\voice-studio\updater.json`.
- Адрес репозитория задаётся при сборке: `-DVOICE_STUDIO_UPDATE_REPO=владелец/имя` (пусто — без автообновления).

**Секретный ключ подписи** лежит вне репозитория: `%USERPROFILE%\.voice-studio\signing-key.pem`.
Храните его резервную копию в надёжном месте: без него уже установленные плагины не примут ни одно обновление,
и пользователям придётся переустанавливать плагин вручную. Если ключ утёк — выпустите версию с новым открытым
ключом, пока старый ещё под вашим контролем.

```
voice-studio/
├─ src/
│  ├─ plugin-main.cpp       точка входа модуля OBS
│  ├─ voice-filter.cpp      фильтр OBS: интерфейс, потоки, «Умная настройка», прослушивание
│  ├─ presets.cpp           готовые стили
│  ├─ settings.hpp          ключи настроек
│  ├─ shared-state.hpp      общие данные фильтра и живого блока (индикаторы, спектр, статус)
│  ├─ ui/                   живой блок в окне фильтра (Qt)
│  │  ├─ live-block.*       уровни, строка состояния, надпись об обновлении, раскладка блока
│  │  ├─ eq-view.*          кривая эквалайзера поверх спектра
│  │  ├─ props-injector.*   встраивание блока на место невидимой строки-метки
│  │  ├─ obs-live.*         связь с настоящим фильтром OBS
│  │  └─ style.hpp, spectrum.hpp, live-link.hpp
│  ├─ update/               автообновление
│  │  ├─ update-core.*      HTTPS, подпись, описание версии, пакет, установка с откатом (без OBS и Qt)
│  │  ├─ updater.*          меню «Сервис», проверка при запуске, окна обновления
│  │  └─ public-key.hpp     открытый ключ для проверки подписи
│  └─ dsp/                  обработка звука, не зависит от OBS
│     ├─ voice-chain.*      вся цепочка: вход → срез гула → ИИ-шумодав → гейт → EQ → де-эссер
│     │                     → компрессор → тепло → смена голоса → громкость → лимитер
│     ├─ denoiser.*         RNNoise + передискретизация для 44.1 кГц
│     ├─ analyzer.*         «Умная настройка»
│     ├─ pitch-shifter.*    фазовый вокодер с сохранением формант
│     ├─ dynamics.hpp       гейт, компрессор, де-эссер, тепло, лимитер
│     ├─ biquad.hpp         фильтры эквалайзера
│     └─ resampler.hpp, fft.hpp, common.hpp
├─ data/locale/            переводы интерфейса (12 языков, ru-RU — основной)
├─ docs/                   скриншоты, GIF и демо-ролики для README
├─ releases/<версия>/      описание изменений для окна обновления и GitHub
├─ third_party/rnnoise/    RNNoise 0.2 (BSD-3-Clause)
└─ tests/                  офлайн-тест, тест в libobs, инструмент обновлений, просмотр и запись демо
```

### Живой блок в окне фильтра

API свойств OBS не умеет показывать свои виджеты, поэтому фильтр добавляет в начало настроек пустую строку
с невидимой меткой, и при отрисовке окна на её место встаёт блок. Если устройство окна в будущей версии OBS
изменится, останется просто пустая строка: настройки продолжат работать, не будет только блока.

Важно: `obs_source_update_properties` заставляет OBS синхронно перестроить окно свойств и удалить старые виджеты,
включая сам блок. Поэтому из обработчиков мыши обновление окна (и окно обновления плагина) откладывается через
`QTimer::singleShot(0, …)`.

### Переводы

Основной язык — `ru-RU.ini`, у всех остальных тот же набор ключей в том же порядке и те же `%d`, `%s`, `%1`.
OBS выбирает файл по языку своего интерфейса; казахского, киргизского и таджикского в OBS 32 пока нет.
